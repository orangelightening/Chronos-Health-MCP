Version: 1.0 (Blue Sky)  ·   Generated: 2026-04-20  ·   Source: Direct reading of source code  ·   Purpose: Authoritative system description

1. Overview

Librarian MCP Server — a Model Context Protocol (MCP) server providing AI models with semantic document search across multiple independent libraries. Fully local, CPU-based, no cloud dependencies.

Architecture

Blue Sky — in-place indexing, per-library ChromaDB, no shadow copies

Language

Python 3.13

MIT License

3. Request Lifecycle

Semantic Search Request

MCP Client → search_library(query="plant taxonomy", library="botany", limit=10) ↓ librarian_mcp.py → FastMCP routes to library_tools.search_library() ↓ Get ChromaDBOrchestrator (lazy singleton)
Clear cached connection for "botany" (force fresh HNSW load)
Create PersistentClient at botany/.librarian/chromadb/
Get collection "botany" (cosine similarity space) ↓ collection.query(query_texts=["plant taxonomy"], n_results=10)
└── ChromaDB embeds query → finds nearest vectors ↓ _format_results(): Convert distance → similarity (1 - distance)
└── Filter None results (stale HNSW entries)
└── Return sorted by score (descending, higher = better)

Add Library Request

MCP Client → add_library(source_path="/home/peter/botany", library_name="botany") ↓ Validate source_path exists
LibraryManager.register_library() ├── Create .librarian/ directory structure
├── Create delivery/ directory (for report output)
├── Create .librarianignore (default excludes)
├── Create .stignore (Syncthing exclusions)
├── Create config.yaml with defaults
├── Initialize ChromaDB (create collection)
└── Add to registry (libraries.yaml) ↓ Set active flag (LibraryStatus.set_active(True)) ↓ Spawn sync_worker.py as subprocess (stdout/stderr → DEVNULL)
├── Worker runs independently in background
├── Worker logs to .librarian/sync_worker.log
└── Return immediately: "Library sync started"

4. Source Code Reference

Entry Point

mcp_server/librarian_mcp.py — Server entry point

Creates FastMCP server, registers tools, handles transport selection. Parses CLI args (--transport, --port, --host, --mode) and reads LIBRARIAN_* environment variables. Modes: Admin (default), LibraryManager, LibraryUser.

Core Components (mcp_server/core/)

library_manager.py — Library registry and lifecycle

  • Registry path: <project>/global_control/.library_control/libraries.yaml
  • register_library() — Creates .librarian/ structure, delivery/ directory, default .librarianignore and .stignore, initializes ChromaDB, adds to registry
  • unregister_library() — Removes from registry, deletes .librarian/ (NOT source files)
  • get_library() / list_libraries() / get_library_config()
  • YAML with atomic write (temp + rename) throughout

indexer.py — File discovery, change detection, indexing coordination

  • index_library() — Main indexing loop (incremental sync)
    • Loads metadata/index.json (SHA-256 checksums, document IDs)
    • Discovers files via _discover_files() with .librarianignore support
    • First pass: checksum comparison → new/changed/skipped
    • Cleanup phase: delete chunks for deleted files ([DELETE]) and updated files ([UPDATE])
    • Second pass: batch process changed files through ChonkieBackend
    • Returns: {added, updated, skipped, deleted, errors}
  • reindex_library() — Full rebuild (clears ChromaDB + metadata first)

chromadb_orchestrator.py — Per-library ChromaDB connections and search

  • get_connection() — Get/create PersistentClient (cached in dict)
  • search_library() — Queries collection, converts distance → similarity (1 - distance), filters None results
  • search_all_libraries() — Sequential search, aggregate, re-rank by score
  • get_library_chunks() — Retrieve all chunks for keyword search
  • _format_results() — Standardized format: {content, metadata, score, library}

library_status.py — Atomic status updates

Status stored in .librarian/config.yaml under status: key. Provides set_active(), is_active(), update_sync_time(), get_status().

ignore_patterns.py — .librarianignore pattern matching

Loads gitignore-style patterns from {library_root}/.librarianignore. Used by Indexer to skip files during discovery.

Backend Components (mcp_server/backend/)

chonkie_backend.py — Semantic chunking + ChromaDB storage

  • Extends ChromaBackend. Query, delete, and stats methods are disabled (raises NotImplementedError). Pure insert-only — all chunk deletion is handled by the Indexer.
  • __init__() pre-loads minishlab/potion-base-32M with force_download=False, wraps in Model2VecEmbeddings, passes to SemanticChunker. Default chunk_size: 512 tokens.
  • chunk_files() — File-type-aware processing:
    • Text (.md, .txt, .rst, .log) → read and chunk
    • Code (.py, .js, .ts, .sh, .bash, .zsh) → read and chunk
    • Config (.json, .yaml, .yml, .toml) → read and chunk
    • HTML (.html) → convert to Markdown via html2text (links preserved, images skipped, no wrapping), then chunk
    • Binary → rejected with warning
  • get_backend_info() — Returns backend configuration and supported extensions

chroma_backend.py — Base ChromaDB operations

Connection management, add_documents(), delete_documents(), get_stats().

factory.py — Backend creation

Configuration (mcp_server/config/)

settings.py — System settings singleton

Defines PROJECT_ROOT, LIBRARIAN_HOME, LIBRARY_REGISTRY, default chunk size, extensions, timeouts. Environment overrides via LIBRARIAN_* prefix.

config_loader.py — YAML configuration loading

load_global_config(), load_library_config(), load_libraries_registry(), atomic writes for config and registry.

server_mode.py — Tool set definitions per mode

LIBRARYMANAGER_TOOLS (18), LIBRARYUSER_TOOLS (14), ADMIN_TOOLS (all + admin_command).

librarian_prompt.py — System prompt for LLM persona

Tools (mcp_server/tools/)

library_tools.py — All 22+ MCP tools + security validation

The largest file in the codebase. Contains constants (command whitelists, banned flags, document extensions), helper functions (is_safe_command(), is_library_path(), is_admin_path(), is_safe_admin_command(), truncate_output()), and tool registration via conditional_tool() decorator that filters by server mode.

keyword_search.py — Text matching engine

Simple substring matching across chunks. Counts occurrences per chunk, sorts by match count (descending).

5. Scripts

Active Scripts

scripts/sync_worker.py — Background sync/rebuild process

  • Run as subprocess by add_library, sync_library_async, rebuild_library_async
  • Creates its own PersistentClient (separate from MCP server)
  • Loads model with force_download=False (cached)
  • Incremental sync: SHA-256 checksums detect changes
  • Deletion detection: finds indexed files not on disk, removes from ChromaDB
  • Logs to {library}/.librarian/sync_worker.log
  • Sets active flag True at start, clears in finally block

Startup Scripts

  • start_multi_mode.sh — Starts LibraryManager (8889), LibraryUser (8890), Admin (8891). PID files in /tmp/, health check after 5 seconds.
  • stop_multi_mode.sh — Graceful shutdown by PID, then force kill after 5 sec, final sweep by port.

9. Tool Reference

Search Tools

search_library(query, library, limit=10)

Semantic search within a single library. Returns chunks with similarity scores (higher = better, 1.0 = identical, 0.0 = unrelated). Clears cached ChromaDB connection for fresh results. Filters None results (stale HNSW entries).

search_library_keyword(keyword, library, case_sensitive=False, limit=None)

Exact text matching across all chunks in a library. Retrieves all chunks via get_library_chunks(), filters by substring. Sorts by match count (most matches first).

search_across_libraries(query, limit=10)

Searches all registered libraries sequentially. Aggregates results, re-ranks by score, returns top N.

Library Management Tools

add_library(source_path, library_name, description="")

Registers a new library and starts background indexing. Creates .librarian/ structure, delivery/ directory, default .librarianignore and .stignore, config.yaml, initializes ChromaDB. Spawns sync_worker.py as background subprocess.

delete_library(library, force=False)

Unregisters library and deletes .librarian/ directory. Does not delete source documents.

sync_library_async(library)

Incremental sync: SHA-256 checksum comparison. Only changed files are re-indexed. Spawns sync_worker.py in background. Returns immediately.

rebuild_library_async(library)

Full rebuild: clears ChromaDB and metadata, re-indexes everything from scratch. Long-running operation (20-30 minutes for full library).

Document Access Tools

list_library_documents(library, limit=50)

Lists indexed documents with metadata from metadata/index.json.

read_library_document(path, library, max_chars=8000)

Reads a document from within a registered library root. Path is relative to the library root.

CLI Tools

execute_command(command, args=None, cwd=None)

Executes whitelisted commands within library roots. 22 allowed commands (ls, cat, grep, find, head, tail, wc, etc.). Validates path against registered library roots. 15 second timeout, 8000 char output limit.

admin_command(command, args=None, cwd=None) Admin only

Expanded whitelist: 27 commands (+ ps, pip, env, printenv, which). Broader path scope: library roots + project source directory. Argument guards block write operations (pip install, ps -k, etc.).

read_document(path, start_line=None, end_line=None, max_chars=8000)

Reads files within allowed directories. Supports head/tail/line-range selection.

list_documents(path=None, extension=None, recursive=True)

Lists documents within a directory path, filtered by supported extensions.

search_documents(query, path=None, extension=None, case_sensitive=False)

Text string search across documents in a directory. Returns matching files and lines with line numbers.

document_summary(path)

Structural summary of a document — headings for markdown, definitions for code, first 10 lines for others.

write_document(path, content, create_dirs=True, library=None)

Writes to {LIBRARIAN_HOME}/{path} sandbox (always). When library is specified, also writes to {library_root}/delivery/{path} — enabling deliverables to sync to remote devices via Syncthing. Path traversal blocked, dangerous patterns blocked. Max 100KB.

server_info()

Returns server configuration, allowed commands, and supported document types.

10. Data Flow Maps

Sync Data Flow

sync_library_async("botany") ↓ library_tools.py: Set active=True, spawn sync_worker.py ↓ sync_worker.py (background subprocess)
├── LibraryManager.get_library("botany") → registry lookup
├── Load config.yaml → get chromadb path, collection name
├── Create ChonkieBackend (load model from cache)
└── Create Indexer(manager, backend) ↓ Indexer.index_library("botany")
├── Load .librarian/metadata/index.json → existing checksums
├── _discover_files() → scan disk, apply .librarianignore ↓ First pass: checksum comparison
├── Unchanged → skip
└── New/changed → queue for processing
↓ Cleanup phase (single ChromaDB connection)
├── [DELETE] Files removed from disk → remove chunks + metadata
└── [UPDATE] Files being updated → remove old chunks
↓ Second pass: batch through backend (pure insert)
├── For each changed file:
│ ├── Read text from disk (or convert HTML → Markdown)
│ ├── SemanticChunker.chunk(text) → chunk objects
│ └── Add new chunks to ChromaDB with metadata
└── Save metadata (checksums, document_ids) to index.json ↓ LibraryStatus: update sync time, doc/chunk count, set active=False

Search Data Flow

search_library("plant taxonomy", "botany", 10) ↓ ChromaDBOrchestrator.search_library() ↓ ├── clear_connection("botany") → discard cached client
├── get_connection("botany") → create fresh PersistentClient
│ └── botany/.librarian/chromadb/
├── get_or_create_collection("botany", cosine space)
├── collection.query(query_texts=["plant taxonomy"], n_results=10)
│ └── ChromaDB embeds query with BAAI/bge-small-en-v1.5
│ └── HNSW index finds 10 nearest vectors ↓ _format_results()
├── For each result: score = 1 - distance (similarity)
├── Filter None documents (stale HNSW)
└── Return [{content, metadata, score, library}, ...]

11. Security Architecture

Seven layers of defense-in-depth:

1
Dynamic Library Boundary

is_library_path() validates paths against registered library roots — not a single SAFE_DIR. Registering a new library automatically extends what the LLM can access.

2
Admin Path Scope

is_admin_path() validates paths against library roots and the project source directory. Only for admin_command.

3
Command Whitelisting

execute_command: 22 allowed commands. admin_command: 27 allowed commands. Both check BANNED_FLAG_COMBOS and DANGEROUS_COMMANDS.

4
Admin Argument Guards

pip install/uninstall/download → BLOCKED. ps -k/-s/--signal → BLOCKED. All admin operations are read-only.

5
Report Write Sandbox

write_document() writes to {LIBRARIAN_HOME}/{path} (always, backward compatible). When the library parameter is provided, also writes to {library_root}/delivery/{path} — delivery path validated to stay within library's delivery directory. Path traversal blocked (.., /, \). Dangerous patterns blocked (password, secret, .env). Max 100KB.

6
Resource Limits

Command timeout: 15 seconds. Output truncation: 8,000 characters. Max write size: 100KB. Max document size: 10MB.

7
.librarianignore

Gitignore-style patterns loaded from {library_root}/.librarianignore. Excludes security files (.env, *.key), dependencies (venv/, node_modules/), databases, build artifacts, and OS files.
