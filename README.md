# Chronos Health MCP

**An MCP server that turns your health records into something you can actually understand.** 

**Version**: 1.0 (Blue Sky) | **License**: MIT | **Status**: Production Ready ✅

---

## The Problem

Chronic disease management happens in the gaps. You get 10–15 minutes with your doctor every few months. You walk out with lab results nobody explained, medication changes you're not sure you understand, and a follow-up appointment three months away.

Over the years, you accumulate a pile of documents — blood work, specialist reports, medication lists, symptom notes, discharge summaries. They sit in folders or patient portals, disconnected from each other. Nobody — not your GP, not your specialist, not you — has the whole picture in front of them at the same time.

**Chronos Health gives you a way to organize that pile and talk to an AI about what's in it.**

It is, at its core, a library. Libraries don't diagnose. They make knowledge accessible. That's what this does.

## What It Does

Chronos Health is a [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) server that indexes your medical documents into searchable libraries on **your own machine**. Your data never leaves your computer. No cloud, no accounts, no API keys. You can  use cloud models as well as local models if you have no security concerns. It all depends on what your chat client offers.

You point it at a directory of health records — lab results, doctor's notes, medication lists, discharge summaries, anything in text or Markdown format — and it builds a searchable knowledge base. Then, using any MCP-compatible AI client, you can search and discuss your records in context.

### What a conversation looks like

```
You: "What was my creatinine trend over the last year?"

Chronos Health: Found 14 lab results across 2025-2026:

  Mar 2026:  136 µmol/L  ⚠️ Highest recorded
  Feb 2026:  113 µmol/L
  Dec 2025:  110 µmol/L
  Sep 2025:  117 µmol/L
  ...

  Your creatinine has been gradually rising. In August 2025 it was
  101, and by March 2026 it reached 136. Reference range is 45-110.
```

```
You: "What medications changed after my second AFib attack?"

Chronos Health: Found in recovery/recovery.md and Heart issues/bp log.md:

  After the December 8, 2025 AFib event (K+ = 3.1):
  - Indapamide reduced from 2.5mg → 1.25mg
  - Potassium chloride supplementation increased to 2200mg/day
  - Cordyceps supplements permanently discontinued
```

The AI can find patterns, retrieve historical context, and show you connections across years of records — because all your documents are indexed and searchable from one place.

## Core Features

- **📚 Multiple patient libraries** — One library per family member. Separate, private, independent.
- **🔍 Semantic search** — Find by meaning, not just keywords. "Which labs showed low potassium?" finds the right results even if the word "low" isn't in the file.
- **🔍 Keyword search** — Exact text matching when you need precise hits on a test name or medication.
- **✍️ Summary reports** — The AI can write health summaries to a sandboxed directory for your review and to share with your doctor.
- **📊 Incremental sync** — Add new lab results, run sync. Only changed files are re-indexed.
- **🔒 Runs locally** — CPU-based, no cloud, no API keys, no data leaving your machine. Your health records stay on your computer.
- **⚡ No GPU required** — Static embedding models use lookup tables, not neural network passes. Runs on any standard PC with 8GB RAM.
- **🛡️ Multi-mode security** — Three server modes with different tool sets. Patients can search and read. Only administrators can manage libraries.
- **🌐 Secure remote access** — Share libraries with family members over a Tailscale tailnet. Your MCP server stays on your machine; clients connect through an encrypted VPN with no ports exposed to the internet.
- **📦 Distributed libraries (optional)** — Mirror libraries to remote devices using Syncthing over Tailscale. Family members edit their own copy; changes sync back automatically. Reports and deliverables written by the MCP sync to the remote device for local pickup. Tested and working across networks.

## Other Uses

Chronos Health works with **any** document collection, not just medical records. You can use it for:

- **Research papers** — Index and search your personal reference library
- **Technical documentation** — Search code docs, architecture notes, API references
- **Botanical collections** — Plant records, garden notes, species identification guides
- **Legal documents** — Contracts, correspondence, case files
- **Genealogy records** — Family history documents, census records, vital statistics
- **Any text documents** — If it's text, Chronos Health can index it

The medical use case is the focus of this release because chronic disease patients need it most. But the underlying engine is a general-purpose document library system.

## Installation

**→ See [INSTALLATION.md](INSTALLATION.md) for complete setup instructions** including server install, MCP client configuration, and creating your first library.

Quick summary:

```bash
git clone https://github.com/orangelightening/Chronos-Health-MCP.git
cd Chronos-Health-MCP
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
./start_multi_mode.sh
```

Then point your MCP client at `http://localhost:8890/mcp` and start asking questions about your records.

### Setting Up a Health Library

1. Create a directory for your health records (e.g., `~/my-health/`)
2. Add your documents as Markdown (`.md`) or text (`.txt`) files. Organize into subdirectories however you like:
   ```
   my-health/
   ├── lab-results/
   │   ├── 2025/
   │   │   ├── 2025-03-10.md
   │   │   └── 2025-06-15.md
   │   └── 2026/
   │       └── 2026-01-13.md
   ├── medications/
   │   └── current-meds.md
   ├── doctor-notes/
   │   └── nephrology-consultation.md
   └── symptoms/
       └── bp-tracking.md
   ```
3. Register it as a library using the LibraryManager mode (port 8889)
4. Sync. Ask questions.

**Tip:** Most patient portals (MyCareCompass, MyChart, etc.) let you download lab results as PDFs. Convert them to Markdown with any PDF-to-text tool before adding to your library. Lab results in simple text format work best.

## How It Works

### Architecture

```
 ┌──────────────────────┐              ┌──────────────────────┐
 │   MCP Client (AI)    │              │   MCP Client (AI)    │
 │  Jan / LM Studio     │              │  Jan (remote, Mac)   │
 └──────────┬───────────┘              └──────────┬───────────┘
            │ localhost                             │ Tailscale VPN
            │ :8890                                 │ :8890
            ▼                                       ▼
  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
                       YOUR MACHINE
  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
            │                                       ▲
            ▼                                       │
┌──────────────────────┐     ┌──────────────────────┐
│  Chronos Health MCP  │     │  Document Libraries   │
│  Server (3 modes)    │────▶│                       │
│                      │     │  my-health/            │
│  • Semantic search   │     │  ├── .librarian/       │
│  • Keyword search    │     │  │   └── chromadb/    │
│  • Library mgmt      │     │  ├── delivery/         │
│  • Report writing    │     │  ├── lab-results/      │
│  • Admin commands    │     │  └── medications/      │
│                      │     │                       │
└──────────────────────┘     │  partner-health/       │  ◄── Syncthing ──► Remote device
                             │  ├── .librarian/       │       (optional, bidirectional)
                             │  │   └── chromadb/    │
                             │  ├── delivery/         │
                             │  └── lab-results/      │
                             └──────────────────────┘
```

Clients connect via localhost on the same machine, or via Tailscale from anywhere on your tailnet. No ports are exposed to the public internet.

- **In-place indexing** — Documents are indexed where they live. No copies, no shadows.
- **Per-library ChromaDB** — Each library has its own isolated vector database.
- **Semantic chunking** — Text is split at semantic boundaries (not just line counts), so search finds the right section within a document.
- **Incremental sync** — SHA-256 checksums detect changes. Only new or modified files get re-indexed.
- **.librarianignore** — Exclude files from indexing using gitignore-style patterns.

### Technology Stack

| Component        | Technology                | Purpose                             |
| ---------------- | ------------------------- | ----------------------------------- |
| MCP Framework    | FastMCP                   | Tool registration, HTTP transport   |
| Vector Database  | ChromaDB                  | Per-library semantic search         |
| Chunking Engine  | Chonkie (SemanticChunker) | Meaning-aware text splitting        |
| Chunking Model   | minishlab/potion-base-32M | Static embeddings (CPU-only, 129MB) |
| Search Model     | BAAI/bge-small-en-v1.5    | ChromaDB default embeddings         |
| HTML Conversion  | html2text                 | HTML → Markdown for indexing        |

## Server Modes

Three server processes with different tool sets, tailored for different users and model sizes.

### LibraryUser (Port 8890) — 14 Tools
For patients and family members. Search, browse, read, and generate reports. No library administration — you can't accidentally delete or rebuild a library.

### LibraryManager (Port 8889) — 18 Tools
Everything in LibraryUser, plus library registration, sync, rebuild, and management tools. For the person setting up and maintaining the family's health libraries.

### Admin (Port 8891) — All Tools
Full access including system diagnostics. For the technical maintainer.

**Why three modes?** Smaller tool sets improve AI accuracy. A model picking from 14 tools makes fewer mistakes than one picking from 22+. It's also a security boundary — a family member searching their records can't accidentally restructure the library.

## Supported File Types

**Indexed:** `.md`, `.txt`, `.rst`, `.py`, `.js`, `.ts`, `.sh`, `.json`, `.yaml`, `.yml`, `.toml`, `.html`, `.css`, `.csv`, `.tsv`

**Not indexed:** PDF, DOCX, images, archives, binaries. Convert to Markdown before creating a library.

## Why This Exists

The current system fails chronically ill patients in a specific way: **nobody has time to sit with you and explain what your own records mean.**

Your doctor is running behind. Your specialist sees you twice a year. Your pharmacist doesn't have your lab history. You're left holding documents full of numbers and ranges and jargon, trying to make sense of your own body with no help.

Chronos Health doesn't replace your doctor. It gives you a way to organize your records so that when you *do* talk to your doctor — or to an AI, or to a family member — the information is findable, connected, and in context.

It is, at its core, a library. Libraries don't diagnose. They make knowledge accessible. That's what this does.
